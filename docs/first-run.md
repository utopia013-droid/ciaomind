# 首次执行：从 Issue 到 PR

## 当前已建立的部分

- 任务入口：Issues → New issue → AI任务，填写类型、目标、验收条件、来源与约束。
- 任务打包配置：Actions → Prepare task。此工作流仅生成 TASK.md，不调用模型或创建 PR。
- 人工交接：将任务包交给你已授权的执行工具，由执行工具在独立分支上修改文件并创建 PR。
- 验收：检查变更范围、实际验证记录和交付物，再由人决定是否合并。

本仓库公开。任务只使用公开信息；客户、财务、家庭资料和凭据不得写入 Issue、代码或任务包。

## 生成任务包

1. 打开仓库 Actions，选择 Prepare task。
2. 点击 Run workflow，选择 main，填写一个仍打开的 Issue 编号（首个任务为 1）。
3. worker 选择拟使用的工具；这只是交接标签，不代表工具已连接。
4. 运行成功后，进入该运行页面，从 Artifacts 下载 task-pack-编号，解压得到 TASK.md。工件保留 7 天。
5. 如果没有 Run workflow 按钮或运行失败，先检查仓库 Actions 权限和日志；不要声称任务包已生成。

## 交给执行工具

在已授权访问此仓库的 Codex 或其他执行环境中，提供 TASK.md，并要求：

> 先读取 AGENTS.md；检查任务目标与验收标准。以当前 main 为基线，在 task/issue-编号 分支实现任务。只修改任务范围内文件，提供实际检查记录，创建关联原 Issue 的 PR。不自动合并，不调用付费 API。

执行前先检查同名分支和现有 PR，复用已有工作，避免重复提交。研究或办公任务可以交付带来源的文档链接，无需强制创建代码 PR。
