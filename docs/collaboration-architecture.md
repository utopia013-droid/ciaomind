# 多智能体协同、反馈控制与语言约定

本文为目标架构和待验证设计，适用于已有私有知识流程及成本规划器。它没有部署新的调度服务，也不表示桌面应用、手机代理或外部模型已连接。

## 1. 优化目标与价值原则

隐私授权、证据正确性、已批准预算、平台规则和最终人工确认是硬边界；在边界内比较合格交付成本、完成时延、人工审核时间和可持续维护成本。质量、速度和价格通常互有取舍，不预设能同时取得三个极值。

先剔除被其他路线全面支配的候选，向用户展示剩余取舍；用户尚未给成本/时间/效果权重时，不虚构综合效用函数。现有routing.py仅按保守费用/质量下界及审核时间提出建议，尚未实现完整的多目标前沿或期限调度。

对于“天人合一”类哲学取向，可提出如下工程解释供本人核对：把人、工具、社区、产业及资源环境视为相互影响的系统；节制不必要调用，尊重平台容量和他人意愿，以长期关系而非短期互动数量衡量收益。此解释不是对用户完整世界观的定论，也不能证明控制稳定、博弈均衡、全球最优或商业成功。

## 2. 谁来协调

| 角色 | 目标职责 | 权限边界 |
| --- | --- | --- |
| 本人 | 核心价值取舍、身份事实、预算、资料外发和对外授权 | 不需逐条处理普通格式问题，但保留暂停和纠正权 |
| 规划协调角色 | 把意图转成任务、验收条件、依赖和待确认事项 | 可建议、不能自行提高预算、扩大权限或裁定个人立场 |
| 确定性调度器（目标能力） | 状态机、任务租约、配额与费用预留、依赖顺序、限次和停止 | 执行已批准规则；任务文本和模型回复不能改写规则 |
| 提炼/研究角色 | 基于证据提出候选、保留出处与未知 | 不将自己的回答记作用户立场 |
| 核验角色 | 核对事实、作者归属、原文和必要字段 | 不以赞同其他模型替代核实 |
| 反方角色 | 给出具体反例、替代解释及边界 | 不以反对数量获取奖励 |
| 综合角色 | 忠实呈现证据、分歧和核心待确认项 | 不抹去异议、不替本人确认 |
| 平台适配器 | 按接口提交授权任务，返回结果、usage与错误 | 无权采购、修改治理策略或添加新连接 |

初期可在当前ChatGPT/Codex工作界面承担规划协调，通过现有任务包交接。目标执行协调者采用本地确定性程序，而不是让一个LLM无限递归委派；它仍需后续实现和真实认证验收。GitHub负责通用流程与版本，不承载私人原文。Muse、WorkBuddy等须按实际产品能力核验为资料入口、执行工具或人工交接端，名称和截图不能证明API/MCP已接通。

## 3. 语言与接口

- 人工治理和任务说明默认简体中文；涉及外文来源时保留原语言、逐字引文及术语对照。需要翻译时另存译文，不替换证据原文。
- 智能体交接使用固定JSON；字段名称采用现有英文标识，如job_id、phase，正文可用中文或任务指定语言。不要只靠聊天摘要传递依赖、授权或完成状态。
- 研究任务可使用来源语言；外部内容按受众语言改写。不同语言的事实、数字、立场强度和适用条件须一致。
- 用Python维护当前本地调度与校验逻辑；提供商适配器保持独立。API/MCP仅在实际受支持并通过认证验证时使用，不为不同角色新增不必要的编程语言栈。
- 不假定英文提示一定更省tokens或更准确。提示语言与版本进入同任务评测，按实际合格率、usage与审核时间选择。
- 当前input.json/output.example.json已提供阶段交接；跨应用全流程接口和统一执行权限拦截器尚未完成。

## 4. 控制论落实为可观测反馈

观测状态：剩余额度与重置、已花费/待对账费用、任务队列、失败类型、独立样本质量、延迟、本人修改与审核分钟、来源及模型版本。余额未知必须保持unknown，不能靠模型估成有余额。

可调整动作：已批准候选内的路线、排队顺序、批量大小、上下文裁剪、最大输出、有限重试和冷却。主张、权限和预算不能作为调度器自由控制变量。

采用两层反馈：

1. 运行层按真实错误和资源观测执行既定规则；硬边界失败立即暂停。当前规划器只建议，不执行此层的外部动作。
2. 治理层定期比较同类样本，提出带理由、代价与回滚条件的策略修订，并形成决议。每次优先改变一个主要变量，保留稳定基线。

目标执行层需全流程预算预留、幂等任务ID、并发租约、超时对账、冷却与回滚。没有这些机制时不能把只读计划称为无人值守运营。动态调参只限已批准范围；未知模型、费用上调、数据条款变化需重新验证。当前没有足够实测数据证明任何控制稳定性。

## 5. 博弈论落实为职责与激励约束

不同角色共享最终合格标准，但分别承担覆盖、核验、反证、忠实综合的责任。作者不能独自宣布最终验收；协调者不能为了完成率跳过审查。

统计实际可用的交付、引用/归属错误、审核时间和回退次数；不按token消耗、篇幅、赞同率、反对数量或流量给模型奖励。多平台可能使用相同底层模型，不视为天然独立；不能用多数票创造事实。

保留少量公开低风险对照样本和人工抽查，检测自评偏差。来自模型的“继续增加十轮讨论”等建议不能改变总调用上限。避免奖励迎合用户或迎合平台；不赞同某个观点本身不是质量失败。

这属于激励相容的工程启发，不宣称已求出形式化均衡。若要建立数学模型，还需先明确参与者、可观测行动、效用、信息结构和实验数据。

## 6. 自适应边界与阶段验收

已实现：私有资料增量处理、四阶段任务包、引用与角色校验、本人确认与公开许可、决议历史、只读成本/质量规划。

待验证：真实跨工具任务交接、账号余额读取、同批独立样本对比和明确的低风险工具授权。可在现有产品内验证，不强制购买新API。

待实现：真实执行协调器、事务配额账本、自动化适配器、持续运行环境、对外发布接口。需要适用授权和实际连接后才能运行。

自动改进仅指可回滚的任务分工、提示和调度策略；禁止自行扩大采集、采购、公开、改写核心价值观或降低审查规则。用户核心判断变化仍通过证据候选、复核、本人确认和新决议完成。
