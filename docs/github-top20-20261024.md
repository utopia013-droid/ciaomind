## 后续批次沿用的适配标准

1. 许可明确：记录实际版本的许可；许可受限或未确认复用权时只保留来源链接，不搬运正文。
2. 维护与版本可核对：记录archived、最近提交、正式发布版和实际依赖要求；教程可作历史参考，运行工具须用已核验的版本。
3. 匹配现有工作：每项对应研究、资料处理、研发或验收的具体缺口；能力重复时保留一个执行入口。
4. 成本与离线边界明确：确定性处理优先本地无模型调用；需要账号、API或渠道时单独记为未接通，不把免费目录当成免费服务承诺。
5. 验收可回读：下载、安装、CLI、真实任务和后台各自留证，输入/产物指纹与局限可核对，仍遵循已有PR协议。

## 已实现的入口

- `scripts/mirror_projects.py`：按完整commit从官方HTTPS地址获取根文件和选定子目录；不执行源码、安装器或hook。复用目录须是独立Git worktree且commit一致。
- `scripts/project_catalog.py list/route/search`：统一列出20项，按能力定位，搜索已落地文档并返回固定commit和行号引用。Git读取禁用fsmonitor/hooks，引用前校验实际blob字节。
- `scripts/rea_worker.py`：REA静态JS/TS分析接入与既有任务一致的输入/回执；保留真实解析失败、覆盖率和资源限制，详见 [REA说明](rea-integration.md)。
- 原有MarkItDown/Trafilatura/DuckDB继续负责确定性文档、正文和表格处理；本次目录作为选型与方法资料，不替换既有流水线。
