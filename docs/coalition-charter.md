# 人与AI协同联盟章程草案

这是由人治理的任务与资源协作网络设计，不表示任何模型公司已加入组织或作出合作承诺。本文为可复用模板，不记录实际用户的财务、健康、订阅或授权。

## 1. 联盟为谁创造什么

人的可持续收益、知情选择、隐私和退出权是硬边界。可把人作为参与决策与反馈的节点建模，但不能把人的权利和时间等同于可消耗的机器配额。人在现实中的判断、关系、行动和责任，不能用模型投票替代。

AI角色是按任务和权限运行的软件，没有独立的经济需求或报酬诉求。所谓角色目标，指可观察、可配置的工作职责；模型没有代表提供商谈判服务条款、隐私规则、账单或额度的权限。其认知和触达受来源可见性、训练与推理能力、上下文、工具权限和核验能力限制，不能视作无限认知。

共同进化首先指协作流程、资料库、提示、分工和评价规则在证据下迭代，不表示底层模型已被重新训练，也不表示系统可以自行扩大权限。人可以纠正模型，模型可提供可检验的反例；不把改变人的立场当作增长指标。

## 2. 参与方的可观察目标与互惠

| 参与方 | 可提供的资源 | 可观察目标与约束 | 互惠方式 |
| --- | --- | --- | --- |
| 项目治理者 | 真实问题、现实经验、资料和评价 | 时间、现金、精力、认识与行动范围；目标和权重由本人决定 | 获得有出处且有实际用途的交付，保留选择和退出权 |
| 规划与执行角色 | 整理、检索、推演、草稿、校验和工具操作 | 误差、上下文、额度、权限与无法访问的资料 | 清晰任务和真实反馈提高交付适配，不要求人为模型利益花钱 |
| 模型与算力平台 | 产品权益、接口、容量、公开合作计划 | 定价、限流、地区、数据条款、可用性和商业运营 | 正常使用、可复现的自愿反馈；需要稳定容量且有价值证据时才评估付费 |
| 工具与聚合服务 | 资料入口、统一接口、状态与用量管理 | 自身费用与上游条件，多个入口可能共享额度 | 减少集成负担，但不制造重复权益或隐瞒下游条件 |
| 开源维护者 | 代码、模型、文档与许可 | 维护精力、许可和托管成本 | 可复现问题、通用修复、测试和文档；不提交私料或索取免费运维 |
| 读者及合作方 | 专业经验、自愿反馈与需求 | 注意力、信任、资料权限和拒绝联系权 | 先提供具体帮助，再根据真实回应判断关系与合作价值 |

平台公开免费层、活动、价格和反馈渠道可以研究；公司内部真实目标函数或模型主观意愿不能据此推知。申请公开合作或补助需单独授权，以实际审批为准；不事先记作可用资源。聊天中的承诺不能改变平台服务边界。

## 3. 人机资源分别记账

人的投入：主动处理分钟、实际现金、本人自评的负担、维护责任。机器投入：输入输出/思考用量、原生积分、请求次数、费用、等待、失败与重试。不同单位不强行相加；没有本人认可的时间单价时，不把人生时间和精力折算成钱。

已有订阅的增量费用可能为零，但不是没有总成本或机会成本。未知余额不计为可用；赠金不计收入；大量调用不计成果；本地运算也有设备与维护成本。

数值资源边界和首要目标尚未确定时，建议仅做有限设计、已有材料整理及零新增现金的可暂停试验，不启动持续后台工作或新增固定审核任务。此默认仅为方案提议，不冒充本人已确认预算。暂停与降低负担不需要用户证明理由。

## 4. 协调、语言和运行限制

一个治理入口、一份私有证据库、统一任务包、最多两条经过验证的执行路线作为初始目标。当前工作界面承担规划，未来由确定性程序管理任务状态、全流程资源预留和停止条件。现有程序仍是任务包、校验与只读路线建议，不能宣称已形成无人值守联盟。

中文用于治理和核心讨论；证据保留原语，译文独立；JSON用于机器交接。角色间继承任务范围、预算、来源与停止条件，委派只能保持或收窄权限。提供商、插件和模型名称不等于已认证连接。

普通问题采用主角色提案、独立核验、综合决策；有明确争议才增加反方。涉及个人立场的提炼保留现有完整三阶段复核。没有新增证据的讨论停止；仅具体未满足的验收项触发有限返工。仍遵守每阶段2次、全流程8次模型尝试的现有建议上限；这些是拟定执行规则，不代表后台调用已经开始。

## 5. 控制与激励

优先检查授权、预算、证据质量，再比较价格、时延、审核时间和合格率。实际权重不明确时展示取舍，不声称全局最优。不为了提高完成率跳过复核，也不为了节省现金把大量审查转嫁给人。

反馈依据为真实错误、本人修改、实际耗时、有效交流和实际收益。作者不自批最终验收；多人赞同不等于独立证据。不能按字数、token消耗、反对数量、对用户的赞同率或内容流量奖励角色。

观测可调整已批准范围内的队列、批量、上下文、路线和冷却。新增平台、提高支出、扩大资料外发、降低质量、改变成功标准或本人核心立场，必须另立决议并取得所需确认。

人与环境相互协调的哲学可以作为价值取向；其具体解释需本人确认，工程效果需实测。它不替代任务证据、预算约束、控制稳定性分析或商业需求验证。

## 6. 四周最小验证提议

不要求连续日更、扩展多平台、购入新工具或承诺新业务。时间上限由本人决定；可选的临时试验上限为全程主动审核60分钟，未确认前不自动安排。每周是检查点，不是必须投入的固定会议。

1. 第一周：从实际可读且获授权的材料提出最多3个真实可服务问题，核对对象、需求和可验证能力；本人选1个。没有证据就提交一个实际案例，不编造职业与市场。
2. 第二周：完成一份短答、清单或一页样稿，优先不超过3个直接来源，进行独立核验。任何对外验证需本人确认对象、内容和动作范围。
3. 第三周：如获真实回应，只修订一版；没有反馈不自动扩平台或宣称市场无需求。只有在授权范围内且有新增信息时才考虑一次跟进，对方拒绝立即停止。
4. 第四周：比较投入与实际用途，决定结束、保留为偶发帮助或开展下一轮。报价请求、付费意向与实际到账分别记录，不承诺收入。

主要人工决策限定为：服务谁的哪个问题；是否认可样稿及验证范围；是否继续及下一轮上限。整理、初稿、核验和总结由工具承担，不能要求人重读全部多智能体讨论。

成功衡量：交付是否实际使用、是否解决具体问题、是否减少可比任务处理时间，或是否产生明确下一步。预计节省、实测节省、意向和现金到账分开；礼貌回应、赠金和模型共识不能当成收入。

## 7. 停止、退出与存档

出现本人要求停止、达到资源上限、授权不明、费用上界不明、来源失效、具体缺陷反复未解决或审核负担超限时，停止相应工作并保存可读状态。达到免费额度不自动切付费，不通过多账号、换key或换入口重复计算权益。

用户可撤销单项任务、角色或全部协作。目标执行层应停止新工作、取消可取消队列、撤回访问，列明已发生费用、不能取消的请求和待清理外部副本；当前工具未统一接入，不能承诺一键撤销所有平台。

每个重要决定记录正文、依据、备选、代价、责任、确认状态、生效与复审条件；本人需求、助手建议、实施记录分开。实际记录仅存私有档案，不上传公开仓库。

继续投入必须能解释对人的价值；本体系不以自身持续运行、规模扩张或消耗额度作为目的。
