# 低成本智能体协同与迭代方案

核验日期：2026-10-21 UTC。以下是公开政策快照，不代表任何人的账号余额、地区资格、已连接状态或未来承诺。资料由多个研究角色独立核验；具体价格、活动、模型版本变化后需重新核验。仓库不保存本人订阅、余额或私人任务记录。下表的“已有”表示使用者如已拥有该权益时的可复用分工示例，不声明仓库所有者的实际订阅。

## 1. 推荐组合与目标

首轮采用“已有订阅承担核心思考、产品内免费权益承担独立任务、本地程序承担确定性操作”。不新增订阅，不为消耗额度制造任务。已有订阅的增量费用可以为零，但续费、机会成本和产品用量上限仍须单列。API 原则上只在自动化节省的人工成本有证据时启用。

| 资源层 | 首轮分工 | 计费与连接边界 |
| --- | --- | --- |
| 已有 ChatGPT Pro / Work / Codex 权益 | 任务分解、核心论证、反方复核、综合、代码与验收 | 按实际已开通能力和剩余用量使用，不假设无限；不是任意 OpenAI API 的免费额度 |
| 已有 DeepSeek 产品权益 | 公开材料的第二意见、中文草稿或独立论证 | App/网页免费与 API 余额分开登记；没有核实 API 赠金时不把它算入自动容量 |
| 已有 WorkBuddy / Buddy AI 权益 | 本地资料整理、格式化、独立任务交接；先用脱敏材料 | 只使用产品公开支持的操作；WorkBuddy 与 WorkBuddy AI 是否同账号同积分池待核验，暂不重复计算 |
| 本地 Python / SQLite | 去重、版本、引用校验、缓存、任务状态、预算计划、报表 | 不需要模型调用；电脑、电费和维护时间不是零成本；暂不购买 GPU |
| GitHub | 通用流程、代码、测试、脱敏任务与 PR | 不存原始对话或私有余额；GitHub 本身不等于免费 LLM 算力 |
| Muse 或替代笔记应用 | 可导出资料的收集、阅读和审核入口 | 不是默认算力提供方；当前没有可调用的匹配插件，不为接入它另购工具 |
| 可选免费 API | 为公开、非敏感、批量任务补充容量 | 实际账号、条款、模型与配额核验后才启用；初始无需同时接完所有平台 |
| 可选低价付费 API | 自动化任务的有限补充、明确失败后的受控升级 | 默认关闭、预算0；不自动充值、升级或从免费切付费 |

算法目标：在固定质量、隐私、时限和额度约束下，降低“完成一项通过验收的任务”的费用与人工时间。不能在未做同任务实测、未读取实际余额时声称已找到全局最优。

## 3. 工作流与节省顺序

1. 本地先去重、筛掉过期/无关材料，仅对新增部分生成任务；不要反复发送全部历史对话。
2. 按任务类别分流：结构化整理、翻译、经济事实核验、个人主张提炼、反方审查不能用同一质量分数比较。
3. 公开材料可进入已授权的免费候选；私有原文仅进明确许可的数据通道；受限资料留本地或人工处理。多家模型不默认收到同一份完整私人记录。
4. 简单格式任务用程序；普通草稿优先已有产品权益；必要的事实与立场复核保留原有三阶段审查，不因省钱省略。
5. 复杂任务才使用多角色；每角色最多2次模型尝试、四角色合计最多8次。超过限额暂停，给出具体缺陷；不能由模型自行增加讨论轮数。
6. 模型缓存按来源指纹、提示版本、模型版本、任务族、语言和数据授权隔离；来源撤销时清理相关缓存。付费估算不假设一定命中服务端缓存。
7. 余额只在官方允许的API/界面可取得时读取，否则记unknown，保留产品内人工交接。余额unknown不是无限；429按官方退避，账号/认证错误暂停，不静默转付费。

任务包仍使用现有 job_id/phase/input.json 与结果JSON接口。提炼、核验、反方、综合可由不同工具接力；WorkBuddy积分和DeepSeek App权益目前只能计入“可人工交接”，尚未验证为后台API。

## 4. 可重复的自适应机制

离线规划器：`python -m knowledge.routing examples/routing-input.json`。默认示例无已验证提供商，预算0，结果为queued。它只生成路线建议，不发请求、不预留实际额度、不改世界观，也不代表已接入免费算力。真实适配器需要另外完成认证与端到端验证。

规划器先过滤：已启用并通过认证验证 → 条款/价格未过期 → 数据范围许可 → 能力与上下文够用 → 配额和冷却允许 → 可确定费用上界 → 同任务真实评测达标。无合格路线则排队。

初始质量门槛：同模型版本/提示版本/任务族/语言/数据等级/基准集/评分规则，最近30天至少20个独立case，95% Wilson通过率下界至少0.80。此阈值是冷启动方案默认值，不是金融事实准确性承诺；事实或归属错误仍是硬失败，核心主张继续本人确认。

评测样本与尝试分别计数：相同case重试不增加独立样本；重复导入的attempt不重复计费。所有失败尝试费用和审核时间仍计入总成本。synthetic仅支持simulation，不能支持live路线推荐。模型或提示变化后重新积累匹配样本，不能继承旧模型分数。

候选路线以 `本次保守费用上界 / 通过率下界` 排序；如本人提供审核时间价格，再计入历史每合格case审核时间。未给时间价格时，金额与分钟分别列出，用审核分钟打破同费用平局。展示历史“所有尝试实际费用/合格case数”，用于评估预测误差；历史0费用不代表新请求0费用。

真实执行层以后必须新增私有事务账本：请求前原子预留最大费用与原生配额；超时但可能已执行时保留预留待对账；完成后用账单/usage结算。每日/月度预算不得只检查通知阈值。当前只读规划器不具备这些保证，因此不会执行任何API请求。

每周提出路由调整，允许在已批准候选内变更排队、缓存、批量与分工。新平台、扩大外发范围、增加付费上限、降低质量阈值、修改核心观点仍需本人决定。世界观候选变化必须重走证据审查；不能将阅读量、模型投票或迎合本人作为真实立场的奖励信号。

## 5. 三轮试验与资源决策

第一轮：离线故障与成本仿真，验证预算0不会产生付费建议、免费耗尽会排队、未授权私料不能路由、重复/模拟样本不能伪造质量。该轮不使用真实平台tokens。

第二轮：在现有已授权工作界面，用同一组脱敏样本验证2条路线。每类先20个独立case；同一提供商的不同提示版本可先比较，不必为了独立性购买新订阅。记录真实积分/用量差、用时、引用错误、人工修改和交付合格率。产品间单位不强行换算，现金与权益消耗分列。

第三轮：胜出路线处理新增材料，保留最多10%的公开低风险样本做已批准候选对照。付费关闭时，试验只能消耗确认可用的已有权益。连续失败、配额未知、条款变更即暂停，保留上一稳定版本。没有真实独立样本前，不自动开启探索算法或宣称已找到最优模型。

本仓库当前已具备第一轮规划与回归测试，另已有一次本次对话的真实多角色试运行（不是跨平台成本基准）。第二、三轮需实际产品任务交接与账号用量信息；当前会话无法直接打开用户电脑WorkBuddy或读取其余额，因此不伪造实验成绩。

费用场景不是采购指令：

- A：保持现有订阅，新增API支出$0，剩余额度不足即排队；总成本仍含已有订阅与人工时间。
- B：验证后只开一个按量备选，例如另行确认的$5/月上限；不必新增月付工具。4k输入+1k输出的Gemini 2.5 Flash-Lite标准推理理论价$0.0008，1,000次约$0.80；按DeepSeek flash当前峰时未缓存价同量约$0.0024/次。均不含搜索、重试、存储、税费或其他计费项，且模型质量未实测，不可直接当完整项目月账单。
- C：只有当稳定任务量、审核时间和现金节省证明必要时，才讨论本地模型或额外订阅；本地推理也计硬件、电费与维护。
